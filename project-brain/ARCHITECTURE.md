## System Design

### Overview

Project Brain follows a **DB-first** architecture:
1. **PostgreSQL** is the source of truth
2. **Specialized stores** (Qdrant, Neo4j, MinIO) support specific features
3. All data originates from and is reconciled with the relational database

```

    ???????????????????????????????????????
    ? • Qdrant (Embeddings)               ?

    ? • LM Studio (LLM - optional)        ?
    ??????????????????????????????????????
```

### Key Principles

1. **Idempotency**: All operations use SHA256 hashing to prevent duplicates
2. **Asynchrony**: Long-running tasks (parse, embed, extract) are async via Celery
3. **Evidence**: All extracted items link back to source documents with quotes
4. **Versioning**: Documents can have multiple versions; queries always use latest
5. **Auditability**: Curation events track all manual edits without overwriting originals
6. **Confidence Scoring**: Extracted items include confidence for human review

### Core Tables

#### `documents` (Root Entity)
```sql
CREATE TABLE documents (
    id UUID PRIMARY KEY,
    filename VARCHAR(255),
    mime_type VARCHAR(100),
    file_size INTEGER,
    original_path VARCHAR(512),    -- MinIO path
    sha256_hash VARCHAR(64) UNIQUE INDEX,  -- Idempotency key
    metadata JSONB,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);
```
**Purpose**: Track uploaded files, prevent duplicates via SHA256

#### `document_versions`
```sql
CREATE TABLE document_versions (
    id UUID PRIMARY KEY,
    document_id UUID FOREIGN KEY,
    version_number INTEGER,
    parsed_path VARCHAR(512),      -- MinIO path to parsed.json
    parsing_status ENUM('pending', 'parsing', 'completed', 'failed'),
    parsing_error TEXT,
    parsing_metadata JSONB,        -- Parser type, page count, etc.
    chunk_count INTEGER,
    created_at TIMESTAMP,
    UNIQUE(document_id, version_number)
);
```
**Purpose**: Support multiple parsing attempts/versions per document

#### `chunks`
```sql
CREATE TABLE chunks (
    id UUID PRIMARY KEY,
    document_id UUID FOREIGN KEY,
    version_id UUID FOREIGN KEY,
    chunk_number INTEGER,
    text_content TEXT,
    page_number INTEGER INDEX,
    section_path VARCHAR(512),     -- e.g., "Chapter1/Section2/SubSection3"
    embedding_vector_id VARCHAR(36), -- Qdrant point ID
    is_embedded BOOLEAN INDEX,
    metadata JSONB,
    created_at TIMESTAMP,
    INDEX(document_id, version_id, chunk_number)
);
```
**Purpose**: Parsed content units; link to embeddings via `embedding_vector_id`

#### `issues`, `action_items`, `decisions`
```sql
CREATE TABLE issues (
    id UUID PRIMARY KEY,
    title VARCHAR(255),
    description TEXT,
    status ENUM('open', 'closed', 'pending') INDEX,
    priority VARCHAR(20),
    subsystem_id UUID FOREIGN KEY,
    well_id UUID FOREIGN KEY,
    evidence_chunk_id UUID FOREIGN KEY,  -- Link to source
    evidence_quote TEXT,                  -- Direct quote from document
    confidence FLOAT,                     -- 0-1 extraction confidence
    is_pending_review BOOLEAN INDEX,
    created_at TIMESTAMP
);
```
**Purpose**: Extracted issues with evidence; confidence scores for review filtering

#### `claims`
```sql
CREATE TABLE claims (
    id UUID PRIMARY KEY,
    subject_id UUID INDEX,           -- facility_id, well_id, subsystem_id
    subject_type VARCHAR(50) INDEX,  -- 'facility', 'well', 'subsystem'
    claim_text TEXT,
    evidence_chunk_id UUID FOREIGN KEY,
    evidence_quote TEXT,
    confidence FLOAT,
    created_at TIMESTAMP,
    INDEX(subject_id, subject_type)  -- Composite for status reports
);
```
**Purpose**: Subject-specific claims extracted from documents

#### `lexicon`
```sql
CREATE TABLE lexicon (
    id UUID PRIMARY KEY,
    term VARCHAR(255) UNIQUE INDEX,
    canonical_form VARCHAR(255),       -- The standard form
    category ENUM('abbreviation', 'synonym', 'term'),
    definition TEXT,
    aliases JSONB,                    -- Alternative forms
    source ENUM('auto', 'manual'),
    confidence FLOAT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);
```
**Purpose**: Controlled vocabulary for transcript correction

#### `transcript_corrections`
```sql
CREATE TABLE transcript_corrections (
    id UUID PRIMARY KEY,
    document_id UUID FOREIGN KEY,
    original_text TEXT,
    corrected_text TEXT,
    diff JSONB,                      -- List of {original, corrected, confidence}
    correction_status VARCHAR(50),
    created_at TIMESTAMP
);
```
**Purpose**: Immutable record of corrections applied to transcripts

#### `entity_mentions`
```sql
CREATE TABLE entity_mentions (
    id UUID PRIMARY KEY,
    chunk_id UUID FOREIGN KEY,
    entity_id UUID,                 -- Reference to entity (polymorphic)
    entity_type VARCHAR(50),        -- 'project', 'facility', 'well', etc.
    mention_text VARCHAR(255),      -- The text as it appears in document
    confidence FLOAT,
    created_at TIMESTAMP,
    INDEX(chunk_id),
    INDEX(entity_id, entity_type)
);
```
**Purpose**: Track entity references in documents for linking

#### `curation_events`
```sql
CREATE TABLE curation_events (
    id UUID PRIMARY KEY,
    event_type VARCHAR(50) INDEX,    -- LINK_FIX, ENTITY_MERGE, LEXICON_ADD, etc.
    object_id UUID,
    object_type VARCHAR(50),
    metadata JSONB,                  -- Event-specific data
    applied BOOLEAN INDEX DEFAULT false,
    created_at TIMESTAMP
);
```
**Purpose**: Immutable audit trail of all manual edits

#### `tasks`
```sql
CREATE TABLE tasks (
    id UUID PRIMARY KEY,
    task_type VARCHAR(50) INDEX,     -- 'parse', 'embed', 'correct', 'extract'
    object_id UUID,                  -- document_id, etc.
    object_type VARCHAR(50),
    status VARCHAR(50) INDEX,        -- 'pending', 'processing', 'completed', 'failed'
    retry_count INTEGER,
    max_retries INTEGER,
    error_message TEXT,
    metadata JSONB,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    INDEX(status, task_type)
);
```
**Purpose**: Track background job status and retries

### Indexing Strategy

```
High-Cardinality (Always Index):
- chunks.document_id (many chunks per document)
- document_versions.document_id
- entities: facility_id ? wells & subsystems
- issues.status, is_pending_review
- chunks.page_number

Composite Indexes (for common queries):
- chunks(document_id, version_id, chunk_number) ? sequential access
- issues(subsystem_id, status) ? facility status reports
- claims(subject_id, subject_type) ? status cards
- tasks(status, task_type) ? worker queue
- entity_mentions(chunk_id, entity_type) ? reverse linking
```

## API Architecture

### REST Principles

- **Resource-oriented**: `/documents`, `/entities`, `/search`, `/reports`
- **Standard HTTP methods**: POST (create), GET (read), DELETE (remove)
- **Pagination**: `?skip=0&limit=10` on list endpoints
- **Filtering**: `/issues?status=open&is_pending_review=true`
- **Error Handling**: Standard HTTP status codes + JSON error bodies

### Request/Response Flow

```
Browser/Client
     ?
     ?? POST /ingest/file (multipart)
     ?  ?? FastAPI Route
     ?     ?? Validate MIME type
     ?     ?? Compute SHA256 (idempotency)
     ?     ?? Check document.sha256_hash (avoid duplicates)
     ?     ?? Upload to MinIO
     ?     ?? Create Document record
     ?     ?? Create DocumentVersion (v1)
     ?     ?? Return IngestResponse {document_id, status}
     ?     ?? Trigger parse_document_task.delay()
     ?
     ?? POST /search (application/json)
     ?  ?? FastAPI Route
     ?     ?? Generate query embedding (BGE-M3)
     ?     ?? Search Qdrant (cosine distance, top-20)
     ?     ?? Extract documents from results
     ?     ?? Rerank with BGE-Reranker-v2-m3
     ?     ?? Return SearchResponse {results, total, limit}
     ?     ?? Client displays with scores
     ?
     ?? GET /documents/{id}
     ?  ?? Query Document
     ?     ?? Fetch with relationships (versions, chunks)
     ?     ?? Return DocumentSchema
     ?     ?? Client shows details + parsing status
     ?
     ?? POST /issues (create extracted issue)
     ?  ?? Create Issue record
     ?     ?? Validate evidence_chunk_id exists
     ?     ?? Set is_pending_review=true (default)
     ?     ?? Return IssueSchema
     ?     ?? Item appears in /pending-review
     ?
     ?? POST /pending-review/approve/{type}/{id}
        ?? Update is_pending_review=false
           ?? Item removed from pending queue
```

### Error Handling

All errors return consistent JSON:
```json
{
  "detail": "Descriptive error message",
  "status": 400  // HTTP status code
}
```

HTTP Status Codes:
- **200 OK**: Success
- **201 Created**: Resource created
- **204 No Content**: Success, no response body
- **400 Bad Request**: Invalid input
- **404 Not Found**: Resource doesn't exist
- **409 Conflict**: Duplicate (e.g., SHA256 already exists)
- **500 Internal Server Error**: Server error (log it!)

## Async Task Processing

### Celery Architecture

```
FastAPI Route
    ?
    ?? parse_document_task.delay(doc_id, version_id)
    ?  ?? Queued to Redis
    ?     ?? Worker picks up
    ?        ?? Download from MinIO
    ?        ?? Call DocumentParser
    ?        ?? Save chunks to DB
    ?        ?? Save parsed.json to MinIO
    ?        ?? Trigger embed_chunks_task.delay()
    ?
    ?? embed_chunks_task.delay(doc_id, version_id)
    ?  ?? Queued to Redis
    ?     ?? Worker picks up
    ?        ?? Fetch all chunks for version
    ?        ?? Generate embeddings (BGE-M3)
    ?        ?? Upsert to Qdrant with payload
    ?        ?? Update chunk.is_embedded=true
    ?        ?? Done
    ?
    ?? correct_transcript_task.delay(doc_id)
    ?  ?? Queued to Redis
    ?     ?? Worker picks up
    ?        ?? Fetch parsed.json from MinIO
    ?        ?? Join all chunks
    ?        ?? Apply Lexicon corrections
    ?        ?? Save TranscriptCorrection record
    ?        ?? Trigger extract_meeting_task.delay()
    ?
    ?? extract_meeting_task.delay(doc_id)
       ?? Queued to Redis
          ?? Worker picks up
             ?? Fetch corrected transcript
             ?? Parse for issues, actions, decisions, questions
             ?? Create records with is_pending_review=true
             ?? Done
```

### Task Retries & Monitoring

```python
@celery_app.task(bind=True, max_retries=3)
def parse_document_task(self, document_id: str):
    try:
        # Process...
        pass
    except Exception as e:
        # Retry after 60 seconds, max 3 times
        self.retry(exc=e, countdown=60)
```

## Search & Embedding Pipeline

### Embedding Generation

**BGE-M3 Model**:
- **Dimensions**: 1024
- **Format**: Dense embeddings (float32)
- **Input**: Text chunks (up to 512 tokens)
- **Inference**: ~1-5 seconds per chunk (depending on GPU)
- **Fallback**: Mock embeddings (for dev without GPU)

**Flow**:
```
Chunk text (e.g., "Pump cavitation detected...")
    ?
[Tokenize & Pad to 512 tokens]
    ?
[BGE-M3 Model]
    ?
[1024-dim vector: [0.12, -0.45, 0.89, ...]]
    ?
[Generate UUID for point_id]
    ?
[Upsert to Qdrant with payload]
```

### Qdrant Collection Structure

```json
{
  "collection_name": "documents",
  "vector_size": 1024,
  "distance": "Cosine",
  "points": [
    {
      "id": "uuid",
      "vector": [0.12, -0.45, ...],  // 1024 floats
      "payload": {
        "doc_id": "uuid",
        "version_id": "uuid",
        "chunk_id": "uuid",
        "page_number": 5,
        "section_path": "Chapter1/Section2",
        "text": "Pump cavitation detected..."  // First 500 chars
      }
    }
  ]
}
```

### Search Process

```
User query: "What issues were detected in the pump?"
    ?
[Embed with BGE-M3] ? [0.15, -0.42, 0.91, ...]
    ?
[Qdrant Search]
    ?? Metric: Cosine similarity
    ?? Top-K: 20 (for reranking)
    ?? Results: [{id, score, payload}, ...]
    ?
[Rerank with BGE-Reranker-v2-m3]
    ?? Model: Cross-encoder
    ?? Input: (query, doc_text) pairs
    ?? Output: Relevance scores 0-1
    ?? Top-10: Sorted by reranker score
    ?
[Return SearchResponse]
    {
      "results": [
        {
          "chunk_id": "...",
          "text": "...",
          "score": 0.92,
          "page_number": 5
        }
      ]
    }
```

### Performance Tuning

**For small datasets (<10K chunks)**:
```python
# Search params
limit = 10
offset = 0
```

**For large datasets (>100K chunks)**:
- Enable Qdrant HNSW indexing:
  ```
  search_params:
    hnsw:
      ef: 128  # Increase accuracy at cost of speed
  ```
- Use quantization:
  ```
  quantization_config:
    scalar:
      type: int8  # Reduce memory usage
  ```
- Batch embeddings:
  ```python
  # Embed 32 chunks at a time instead of 1
  embeddings = embedding_service.embed_texts(chunk_texts)
  ```

## Entity Management

### Polymorphic Entity Pattern

Instead of separate tables for each entity type, use:
```sql
-- Flexible approach: each entity type has its own table
-- But entity_mentions is polymorphic

entity_mentions:
  - chunk_id: points to document chunk
  - entity_id: UUID (e.g., facility_id)
  - entity_type: 'facility' | 'well' | 'subsystem' | ...
  - mention_text: "Production Platform A"
```

**For status reports**, query all items for a subject:
```python
# Get status for Facility #123
issues = db.query(Issue).filter(Issue.facility_id == facility_id).all()
claims = db.query(Claim).filter(
    Claim.subject_id == facility_id,
    Claim.subject_type == 'facility'
).all()
```

### Entity Linking

**Current approach**: Keyword matching + Lexicon lookup
```python
# In meeting_extractor.py
for entity_type in ['project', 'facility', 'well', 'subsystem']:
    for entity in db.query(Entity).filter_by(type=entity_type).all():
        if entity.canonical_name in transcript:
            create_entity_mention(chunk_id, entity.id, entity_type)
```

**Future**: Fine-tuned NER model or LLM-based linking
